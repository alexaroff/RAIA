## Эксперимент №2 — Переход на WhisperX Turbo

**Цель:** улучшить скорость и качество транскрипции на M2 8GB.

### Проблема 1 — Таймаут при загрузке модели

**Симптом:** `ReadTimeoutError` при загрузке через Hugging Face.

**Решение:** модель скачана вручную через `curl`, размещена локально.
~/whisper_models/turbo/

---

### Проблема 2 — Конфликт версий библиотек

**Симптом:** `ImportError` — конфликт `transformers` и `huggingface_hub`.

**Решение:** откат версии:

```bash
pip install huggingface-hub==0.34.0
```

---

### Проблема 3 — Конфликт PyTorch и Pyannote

**Симптом:** `_pickle.UnpicklingError` — несовместимость PyTorch 2.8 и Pyannote.

**Решение:** отказ от Pyannote, переход на Silero VAD:
--vad_method silero

---

### Проблема 4 — Перегрев и нагрузка на M2

**Симптом:** высокая температура, зависания при обработке длинных файлов.

**Решение:** оптимизация параметров запуска:

```bash
export OMP_NUM_THREADS=2
```

Увеличены `batch_size` и `chunk_size`. Добавлена предобработка аудио через FFmpeg перед передачей в WhisperX.

## Эксперимент №5 — Автоматизация разметки ролей через API

**Цель:** автоматически размечать транскрипт по ролям HR / CAND через LLM API.

### DeepSeek API
**Результат:** ❌ Ошибка 402 Insufficient Balance — API платный, бесплатного tier нет.

### Gemini API
**Результат:** ✅ Работает. Модель `gemini-2.0-flash`, бесплатный tier. Качество высокое.

### Groq API
**Результат:** ✅ Работает. Модель `llama-3.3-70b-versatile`, бесплатный tier. Качество высокое.

### Реализация

Создан скрипт `role_tagger.py` с поддержкой двух провайдеров:

```bash
python role_tagger.py groq    # через Groq API
python role_tagger.py gemini  # через Gemini API
```

Скрипт читает `output/interview.txt`, отправляет в LLM с промптом из `prompts/role_tagging.txt`, сохраняет результат в `output/interview_roles.txt`.

API ключи хранятся в `.env` файле:
GROQ_API_KEY=...

GEMINI_API_KEY=...

Новое окружение для API: `raia-env-311` (Python 3.11)

**Итог:** рабочий стек — Groq API (основной) + Gemini API (резервный).

## Эксперимент №6 — Локальный Web UI (Gradio)

**Цель:** создать удобный интерфейс для работы с пайплайном без терминала.

**Стек:** Gradio 4.43.0, Python 3.9, subprocess

### Проблема 1 — Баг в gradio-client с Python 3.9

**Симптом:** `TypeError: argument of type 'bool' is not iterable`

Возникал в функции `_json_schema_to_python_type` в `gradio_client/utils.py`.

**Решение:** патч через вставку guard на строке 901:

```python
if not isinstance(schema, dict):
    return "any"
```

---

### Проблема 2 — localhost недоступен на macOS

**Симптом:** `ValueError: When localhost is not accessible, a shareable link must be created`

**Решение:** явное указание `server_name` при запуске:

```python
app.launch(server_name="0.0.0.0", server_port=7860, inbrowser=True)
```

---

### Проблема 3 — Версии gradio и gradio-client жёстко связаны

**Симптом:** откат одного пакета без другого невозможен.

**Решение:** использовать `gradio==4.43.0` — единственная стабильная версия под Python 3.9 с патчем из Проблемы 1.

## Эксперимент №7 — Переход на полностью локальный стек (tool-local-v1)

**Дата:** 24 июля 2026  
**Цель:** выбрать и реализовать золотую середину локальной транскрипции под M2 8 ГБ с приоритетом русского языка, без облака, с возможностью масштабирования.

### Сравнение актуальных вариантов (2026)

| Решение | Качество RU | Скорость M2 | Peak RAM (примерно) | Зрелость Python | Комментарий |
|---------|-------------|-------------|---------------------|-----------------|-------------|
| **mlx-whisper + large-v3-turbo** | Высокое | Отлично (MLX + ANE/Metal) | 1.6–2.5 ГБ | Высокая | **Выбран как основной**. Native Apple Silicon. |
| whisper.cpp (CoreML/Metal) | Высокое | Отлично | 1–3 ГБ (квантизация) | Средняя (bindings) | Отличный кандидат, но больше CLI-ориентирован |
| GigaAM-v3 (MLX community) | **SOTA RU** | Отлично (~20–40× RT) | ~0.5–1 ГБ | Средняя (порт) | Лучший pure-Russian. Планируем как backend №2 |
| Parakeet TDT v3 (CoreML) | Хорошее (WER ~5.5% RU) | Экстремально быстро | Низкое | Низкая (Swift) | Идеален для диктовки, менее удобен для длинных интервью |
| WhisperX Turbo + Silero (старый) | Высокое | Хорошо | 3–5+ ГБ + конфликты | Средняя | Отклонён: память, библиотеки, перегрев |
| faster-whisper | Высокое | Среднее (CPU на Mac) | 2–4 ГБ | Высокая | Слабо использует Apple GPU |

**Ключевые выводы перепроверки:**
- На Apple Silicon в 2026 побеждает либо MLX, либо CoreML/whisper.cpp. PyTorch-стеки (WhisperX, NeMo) проигрывают по памяти и стабильности на 8 ГБ.
- GigaAM-v3 — реальный SOTA по русскому (Sber, open MIT, e2e с пунктуацией). Community MLX-порт уже есть (al-bo/gigaam-v3-rnnt-mlx, 423 МБ fp16). Это стратегический бэкап / будущий основной для РФ-сегмента.
- large-v3-turbo даёт почти large-v3 качество при заметно меньшей памяти и скорости — идеальный компромисс для 8 ГБ.
- Silero VAD остаётся лучшим лёгким VAD; torch overhead можно терпеть, либо перейти на ONNX.

### Реализовано в ветке

- `tool/transcription/` — полный пайплайн:
  - `preprocess.py` — FFmpeg → 16 kHz mono
  - `vad.py` — Silero (с graceful fallback)
  - `pipeline.py` — `LocalTranscriber` + `TranscriptionResult` (txt/json/srt)
  - `cli.py` — готовый CLI
- Ограничение потоков (`OMP_NUM_THREADS=2`) вшито
- Модели переключаются одной строкой (`turbo` / `medium` / `large`)
- API уже готов к добавлению второго backend (GigaAM)

**Статус:** ✅ Базовый рабочий пайплайн реализован и запушен. Требует тестирования на реальных интервью пользователя.

### Доработки после базовой реализации (тот же день)

Добавлено без запуска на железе:

1. **Segment-wise transcription** — при длительности ≥ 90 с и наличии VAD-сегментов каждый кусок режется FFmpeg’ом, транскрибируется отдельно, таймстемпы сдвигаются. Существенно снижает peak memory на длинных интервью.
2. **Автовыбор модели** по `psutil.virtual_memory()` (`model = "auto"`).
3. **config.toml + RAIA_* env** — единый источник дефолтов с приоритетом CLI → env → toml → hardcoded.
4. **GigaAMBackend** — реальный download community MLX-порта (`al-bo/gigaam-v3-rnnt-mlx`) + понятный NotImplementedError до появления pure-MLX decoder’а. Архитектура готова к подключению.

**Текущий статус 6.1:** код готов к первым реальным прогонам на M2 8 ГБ.

### Риски и следующие шаги

- **Риск 1:** mlx-whisper на очень длинных файлах (>45–60 мин) всё ещё может давить на 8 ГБ → мониторить, при необходимости форсировать chunking + VAD-only segments.
- **Риск 2:** Community GigaAM MLX-порт может отстать → мониторить официальный репозиторий Sber.
- **Следующее:** 
  1. Прогнать 3–5 реальных интервью, замерить RTF + peak memory (Activity Monitor).
  2. Довести GigaAM backend до рабочего inference.
  3. Перейти к настоящей диаризации (фаза 6.2).
