## Эксперимент №2 — Переход на WhisperX Turbo

**Цель:** улучшить скорость и качество транскрипции на M2 8GB.

### Проблема 1 — Таймаут при загрузке модели

**Симптом:** `ReadTimeoutError` при загрузке через Hugging Face.

**Решение:** модель скачана вручную через `curl`, размещена локально.
~/whisper_models/turbo/

---

### Проблема 2 — Конфликт версий библиотек

**Симптом:** `ImportError` — конфликт `transformers` и `huggingface_hub`.

**Решение:** откат версии:

```bash
pip install huggingface-hub==0.34.0
```

---

### Проблема 3 — Конфликт PyTorch и Pyannote

**Симптом:** `_pickle.UnpicklingError` — несовместимость PyTorch 2.8 и Pyannote.

**Решение:** отказ от Pyannote, переход на Silero VAD:
--vad_method silero

---

### Проблема 4 — Перегрев и нагрузка на M2

**Симптом:** высокая температура, зависания при обработке длинных файлов.

**Решение:** оптимизация параметров запуска:

```bash
export OMP_NUM_THREADS=2
```

Увеличены `batch_size` и `chunk_size`. Добавлена предобработка аудио через FFmpeg перед передачей в WhisperX.

## Эксперимент №5 — Автоматизация разметки ролей через API

**Цель:** автоматически размечать транскрипт по ролям HR / CAND через LLM API без ручного вмешательства.

### DeepSeek API
**Результат:** ❌ Ошибка 402 Insufficient Balance — API платный, бесплатного tier нет.

### Gemini API
**Результат:** ✅ Работает. Модель `llama-3.3-70b-versatile`, бесплатный tier.
Разметка ролей на тестовом транскрипте — качество высокое, все реплики определены верно.

### Groq API
**Результат:** ✅ Работает. Модель `llama-3.3-70b-versatile`, бесплатный tier.
Разметка ролей на тестовом транскрипте — качество высокое, все реплики определены верно.

### Реализация

Создан скрипт `role_tagger.py` с поддержкой двух провайдеров:

```bash
python role_tagger.py groq    # через Groq API
python role_tagger.py gemini  # через Gemini API
```

Скрипт читает `output/interview.txt`, отправляет в LLM с промтом из `prompts/role_tagging.txt`, сохраняет результат в `output/interview_roles.txt`.

API ключи хранятся в `.env` файле:
GROQ_API_KEY=...

GEMINI_API_KEY=...

Новое окружение для API: `raia-env-311` (Python 3.11)

**Итог:** рабочий стек — Groq API (основной) + Gemini API (резервный).

**Статус:** ✅ Завершено

## Эксперимент №6 — Локальный Web UI (Gradio)

**Цель:** создать удобный интерфейс для работы с пайплайном без терминала.

**Стек:** Gradio 4.43.0, Python 3.9, subprocess

### Проблема 1 — Баг в gradio-client с Python 3.9

**Симптом:** `TypeError: argument of type 'bool' is not iterable`

Возникал в функции `_json_schema_to_python_type` в `gradio_client/utils.py` — функция получала `bool` вместо `dict` и падала на проверке `"const" in schema`.

**Решение:** патч через вставку guard на строке 901:

```python
if not isinstance(schema, dict):
    return "any"
```

Баг повторялся на нескольких проверках (`"const"`, `"enum"`, `"type"`) — все пофикшены последовательно.

---

### Проблема 2 — localhost недоступен на macOS

**Симптом:** `ValueError: When localhost is not accessible, a shareable link must be created`

**Решение:** явное указание `server_name` при запуске:

```python
app.launch(server_name="0.0.0.0", server_port=7860, inbrowser=True)
```

---

### Проблема 3 — Версии gradio и gradio-client жёстко связаны

**Симптом:** откат одного пакета без другого невозможен — pip выдаёт `ResolutionImpossible`.

**Решение:** использовать `gradio==4.43.0` — единственная стабильная версия под Python 3.9 с применением патча из Проблемы 1.
