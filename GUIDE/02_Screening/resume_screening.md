# Скрининг резюме и профилей

**Скрининг резюме и профилей** — это быстрая структурированная оценка кандидата по письменным источникам (резюме, LinkedIn, HeadHunter, GitHub и др.) до телефонного/видео-скрининга.

Цель — за минимальное время отделить тех, кто явно не проходит must-have, от тех, с кем имеет смысл разговаривать.

> Хороший скрининг резюме — это не «прочитал и решил». Это воспроизводимый процесс с заранее определёнными критериями, который снижает bias и экономит время на следующих этапах.

---

## Зачем это важно

На большинстве позиций объём входящих кандидатов (отклики + sourcing) значительно превышает количество людей, которых реально можно качественно проскринить голосом. Без системного подхода к резюме происходит одно из двух:

- Слишком много слабых кандидатов доходит до звонка → перегруз и потеря фокуса.
- Слишком много сильных кандидатов отсеивается по формальным или поверхностным признакам → потеря таланта.

Качественный скрининг резюме решает обе проблемы одновременно.

---

## Как структурировать чтение резюме / профиля

Не читайте резюме «сверху вниз как историю». Используйте целевой порядок, завязанный на критерии позиции.

### Рекомендуемый порядок (60–90 секунд на первичную оценку)

1. **Последние 2–3 места работы**  
   Что делал? На каком уровне? Есть ли релевантный опыт прямо сейчас?

2. **Ключевые достижения и метрики**  
   Есть ли цифры, scope, impact? Или только перечисление обязанностей?

3. **Технологии / навыки / стек** (для технических ролей)  
   Совпадение с must-have. Насколько свежий опыт?

4. **Карьерная траектория**  
   Рост, стагнация, хаотичные переходы, длинные гэпы.

5. **Образование и дополнительное**  
   Только если это действительно must-have или сильный сигнал.

6. **Формальные сигналы**  
   Оформление, ошибки, длина, фото (на HH), желаемая зарплата, готовность к релокации.

> Правило: сначала ищите **причины сказать «нет»** по must-have. Только если must-have закрыты — ищите причины сказать «да».

## Ключевые сигналы

### Положительные сигналы

| Сигнал | Что обычно означает |
|--------|---------------------|
| Конкретные метрики и impact | Человек умеет думать результатами, а не процессами |
| Рост ответственности внутри компаний | Карьерная динамика и признание |
| Релевантный стек + свежий опыт (1–2 года) | Меньше риска «устаревших» знаний |
| Короткие, ёмкие формулировки | Умение выделять главное |
| Активность в GitHub / открытые проекты (для инженеров) | Реальная hands-on практика |
| Логичные переходы между ролями | Осознанная карьера |

### Настораживающие сигналы (не всегда red flag)

| Сигнал | Как интерпретировать |
|--------|----------------------|
| Частая смена работы (каждые 8–14 месяцев) | Может быть норма в определённых индустриях или на junior-этапе. Требует проверки мотивации. |
| Длинные гэпы | Нужен контекст (учёба, проект, личные обстоятельства, фриланс). Не автоматический отказ. |
| Только обязанности без результатов | Слабый сигнал impact. Часто встречается у людей из больших корпораций. |
| Очень общее описание («участвовал в разработке») | Низкая конкретика. Стоит уточнить на звонке. |
| Несовпадение дат между резюме и LinkedIn/HH | Возможная неаккуратность или приукрашивание. |
| Желаемая зарплата сильно выше/ниже рынка | Либо нереалистичные ожидания, либо ошибка в позиционировании. |

## Особенности по платформам

### LinkedIn
- Часто более «маркетинговый» стиль.
- Смотрите Activity, Recommendations, Featured.
- Профиль может быть сильно устаревшим даже у сильных специалистов.
- Отсутствие фото или скудный About — не сигнал качества.

### HeadHunter (hh.ru)
- Более формальный и «советский» формат у многих кандидатов.
- Часто указаны желаемая зарплата, график, готовность к переезду — это полезные фильтры.
- Фото и возраст видны — это повышает риск bias, нужно сознательно контролировать.
- Многие сильные senior-специалисты давно не обновляют резюме на HH. Отсутствие актуального резюме ≠ отсутствие кандидата.

### GitHub
- Для инженеров часто самый честный сигнал.
- Смотрите не количество репозиториев, а:
  - Активность за последние 6–12 месяцев
  - Качество кода в собственных проектах
  - Contributions в чужие репозитории
  - Используемые языки и инструменты
- Пустой или «декоративный» GitHub у backend/frontend-разработчика middle+ — повод для дополнительного вопроса.

### Другие источники
- Habr Career, TenChat, портфолио, персональный сайт — используйте как дополнительные сигналы, а не как основной фильтр.

## Техники быстрого скрининга

**1. Must-have first**  
Составьте короткий чек-лист из 3–5 жёстких требований. Если хотя бы одно не закрыто — дальше не читаете.

**2. Двухпроходный метод**  
- Первый проход (20–40 сек): только must-have + последние места работы.  
- Второй проход (только для прошедших): impact, траектория, дополнительные сигналы.

**3. Калибровка с Hiring Manager**  
Раз в несколько недель показывайте 5–7 резюме, которые вы пропустили и которые отклонили. Синхронизируйте «что считается достаточным».

**4. Фиксация решения**  
Даже короткое: «Pass — закрывает must-have по стеку и уровню, есть impact в последней роли» или «Reject — нет коммерческого опыта с X, только pet-проекты».

## Типичные ошибки и анти-паттерны

- Читать резюме как художественный текст вместо поиска конкретных сигналов.
- Отсеивать по отсутствию «правильных» названий компаний или вузов без контекста.
- Слишком сильно весить годы опыта («нужно ровно 5+ лет»).
- Игнорировать GitHub на технических ролях и смотреть только LinkedIn/HH.
- Принимать решение только по оформлению и наличию/отсутствию опечаток.
- Не фиксировать, почему кандидат прошёл или не прошёл (потом невозможно улучшать процесс).
- На российском рынке автоматически отсеивать кандидатов без актуального резюме на HH.

---

## Практический чек-лист скрининга резюме

- [ ] Must-have критерии определены и согласованы с менеджером
- [ ] Первый проход занимает не больше 40–60 секунд
- [ ] Решение (pass/reject) + краткое обоснование фиксируется
- [ ] Для технических ролей проверяется GitHub / портфолио
- [ ] На HH учитываются зарплатные ожидания и логистика
- [ ] Есть регулярная калибровка с Hiring Manager
- [ ] Bias-контроль: решение не принимается по фото, возрасту, полу, названию вуза
