# Каналы и платформы

Сильный sourcing почти никогда не строится на одном канале. Разные платформы дают разный тип кандидатов, разный уровень шума и разную конверсию в ответ.

Ниже — практическая карта основных каналов 2025–2026 годов с указанием, когда какой канал работает лучше всего.

---

## LinkedIn — основной канал для большинства ролей

LinkedIn остаётся самым универсальным инструментом для поиска специалистов уровня middle+ в большинстве индустрий.

### Что использовать

| Инструмент                  | Для кого                        | Ключевые возможности                              |
|-----------------------------|---------------------------------|---------------------------------------------------|
| **Бесплатный LinkedIn**     | Начинающие, низкий объём        | Базовый поиск, ограниченная выдача                |
| **LinkedIn Recruiter Lite** | Рекрутеры с умеренным объёмом   | Расширенные фильтры, InMail, проекты              |
| **LinkedIn Recruiter**      | Команды с высоким объёмом       | Полный функционал, Advanced search, аналитика     |
| **Sales Navigator**         | Иногда используется рекрутерами | Хорошие фильтры по компании и активности          |

### Сильные стороны
- Огромная база пассивных кандидатов
- Возможность смотреть активность, рекомендации, посты
- InMail + Connection Request как основные точки контакта
- Хорошая поддержка Boolean в Recruiter

### Слабые стороны
- Высокая конкуренция (особенно на популярных ролях)
- Алгоритм сильно влияет на выдачу
- Многие сильные специалисты редко обновляют профиль
- Растущий объём AI-спама снижает общую response rate

**Когда использовать в первую очередь:** почти всегда, особенно для office-based и hybrid ролей middle–senior уровня.

---

## GitHub — критичный канал для инженеров

Для backend, frontend, mobile, DevOps, data и ML-ролей GitHub часто даёт более качественные сигналы, чем LinkedIn.

**Что смотреть:**
- Активность в репозиториях (не только количество stars)
- Языки и технологии в профиле
- Contributions за последние 6–12 месяцев
- Open-source проекты и их качество
- Location и email (иногда открыт)

**Как искать:**
- Поиск по языку + location
- Поиск по конкретным библиотекам/фреймворкам
- Анализ contributors популярных проектов в нужном стеке

> GitHub особенно силён, когда нужно найти людей с реальной hands-on экспертизой, а не только с «правильными» словами в LinkedIn.

## Другие важные каналы

### Stack Overflow / специализированные Q&A
Всё ещё полезен для поиска людей, которые активно решают сложные технические задачи. Менее эффективен для массового sourcing, но даёт высокое качество сигналов.

### Telegram
Критически важен для рынков СНГ, части Восточной Европы и некоторых нишевых IT-сообществ.

- Профильные чаты и каналы по стекам
- Закрытые сообщества
- Возможность прямого контакта

Требует аккуратного подхода: спам в Telegram убивает репутацию быстрее, чем на LinkedIn.

### X (Twitter)
Хорош для поиска людей, которые активно делятся экспертизой (особенно Product, Design, Engineering leadership, AI/ML). Полезен как дополнительный канал для персонализации outreach.

### Reddit
Сильные сообщества (r/cscareerquestions, r/ExperiencedDevs, нишевые сабреддиты). Больше подходит для понимания рынка и мягкого присутствия, чем для массового холодного поиска.

### Нишевые платформы и job boards
- Wellfound (бывший AngelList) — стартапы
- Otta / другие европейские платформы
- Habr Career, Хабр (для русскоязычного IT)
- TenChat, Сетка и аналоги (СНГ)
- Специализированные доски по дизайну, product, data и т.д.

### Реферальные программы
Один из самых высококонверсионных каналов при правильной организации. Сильные сотрудники часто знают сильных кандидатов, которых не видно в открытом поиске.

### Offline и semi-offline
- Конференции и митапы
- Community-события
- Alumni-сети
- Личные нетворкинг-контакты

Эти каналы медленнее масштабируются, но часто дают очень высокое качество и response rate.

## Как выбирать каналы под задачу

| Тип роли / ситуация                    | Приоритетные каналы                          |
|----------------------------------------|----------------------------------------------|
| Senior+ Backend / Infra / ML           | GitHub + LinkedIn + Telegram (если релевантно) |
| Product / Design / Marketing           | LinkedIn + X + нишевые сообщества            |
| Роли в СНГ / русскоязычный рынок       | LinkedIn + Telegram + Habr + TenChat         |
| Стартапы / early-stage                 | Wellfound + LinkedIn + личные сети           |
| Очень узкие / редкие специалисты       | GitHub + конференции + рефералы + X-Ray      |
| Массовые middle-роли                   | LinkedIn + job boards + рефералы             |

**Правило:** всегда начинайте с 2–3 каналов, а не с одного. Один канал почти всегда создаёт слепые зоны.

---

## Практические принципы работы с каналами

- Не путайте «где кандидат есть» и «где он готов отвечать». Наличие профиля ≠ готовность к диалогу.
- На каждом канале свой «язык» и норма общения. То, что работает в LinkedIn InMail, часто выглядит токсично в Telegram.
- Ведите учёт source of hire. Через 3–6 месяцев становится очевидно, какие каналы реально закрывают позиции, а какие только создают иллюзию активности.
- Обновляйте карту каналов раз в 6–12 месяцев. Платформы и поведение кандидатов меняются.

---

## Типичные ошибки

- Использовать только LinkedIn на всех ролях.
- Игнорировать GitHub на технических позициях.
- Спамить в Telegram и закрытых сообществах.
- Не отслеживать, какой канал даёт реальных hires.
- Считать, что «чем больше каналов — тем лучше» (без системы это приводит только к хаосу).
